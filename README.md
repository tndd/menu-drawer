# メニュードロワー

メニューバーのトレイボタンを押すと、収納したアイコンをメニューバーの**下**に展開する小さなMacアプリです。画面収録を使わず、**アプリの通常アイコン＋名前**を縦に並べます。項目を選ぶと、元アプリのメニューを開きます。

## 起動

`build/MenuDrawer.app` を開いてください。検証環境は Apple Silicon / macOS 15.8.1 です。

1. 設定画面の「権限を設定」から、macOSの設定で **MenuDrawerのアクセシビリティだけ**を許可します。画面収録は不要です。
2. ⌘キーを押しながら、収納したいアイコンをメニューバーの「│」より左へ移動します。「│」自体はトレイボタンの左に置きます。右側のアイコンは常時表示されます。
3. 「収納を開始」を押します。以降はトレイボタン1つで開閉できます。パネル外のクリック、Escでも閉じます。
4. 配置の変更や終了は、トレイボタンを右クリックします。「終了して元に戻す」で収納を解除して終了します。

アプリを再ビルドしたあとに「未許可」と表示されたら、macOSの「プライバシーとセキュリティ → アクセシビリティ」でMenuDrawerをオフ→オンにしてください。表示が変わらない場合はアプリを終了して再起動します。設定上はオンなのにアプリが未許可のままなら、古い署名の登録が残っている可能性があります。アプリを終了し、一覧のMenuDrawerを一度削除して、現在の `build/MenuDrawer.app` を追加し直してください。

macOSが移動を許可しない時計などの固定項目は、そのまま表示します。ログイン時の自動起動は設定しません。

## 最小限の権限

**必要なのはアクセシビリティだけです。** 項目の名前と位置を読み、選んだ項目のメニューを開くために使用します。アイコン画像には各アプリが提供する通常のアプリアイコンを使います。

画面収録API、画面収録ライブラリ、その権限確認・要求はすべて削除しました。画面やウィンドウの画像を取得せず、ネット送信も行いません。ウィンドウの位置情報は、収納対象の判定とメニューが開いたことの確認に使用します。

メニューバー固有の絵柄や点滅などは再現しません。アプリがアクセシビリティで項目名や状態を公開していれば、パネルを開くときに文字として取得します。アプリアイコンがない場合は汎用アイコンを表示します。

アクセシビリティで一意に特定できた項目だけを表示します。対応していないアプリのアイコンは、配置設定で区切りの右側へ戻して元の場所で操作してください。メニュー操作が失敗した場合はエラーを表示します。

## ビルドと検証

Xcode Command Line Tools のSwiftだけでビルドできます。外部パッケージは使用しません。

```sh
scripts/build.sh
scripts/test.sh
scripts/test.sh --integration
```

統合検証は実行する端末のアクセシビリティ権限を必要とします。通常起動中のMenuDrawerを終了してから実行してください。検証用プロセスとアプリを起動し、以下を確認します。終了時には検証プロセスを停止します。

- 画面収録の許可状態を記録し、収納した項目の通常アイコン・名前・操作対象を取得する。
- 別プロセスの収納中の項目を操作し、元のメニューウィンドウが実際に表示される。
- 設定画面の「収納を開始」、トレイボタン、パネル内の項目をアクセシビリティ経由で操作する。
- パネルがメニューバーの下に現れ、パネルから元のメニューが開く。

`build/tests/panel.png` はテスト中のパネル自身のビューを描画した画像です。画面全体や他アプリを撮影したものではありません。`--validation-output` と `--preview` は明示した出力先へアプリ自身の描画結果だけを保存する検証用オプションです。

```sh
build/MenuDrawer.app/Contents/MacOS/MenuDrawer --preview /絶対パス/preview.png
```

## 実装と検証範囲

Swift + AppKitで新規実装しています。収納には幅の大きい `NSStatusItem`、操作には `AXUIElementPerformAction` を使用します。ローカル用のアドホック署名で、配布用のApple公証は行っていません。

macOS 15.8.1で、画面収録が未許可のままビルド、配置境界の8検証、収納項目の取得、実パネルから元メニュー表示までの統合検証が成功しました。実パネルの文字と通常アイコンも目視確認しています。自動検証は端末のアクセシビリティ権限で起動したプロセスに対して実施しています。

各アプリが独自に実装するメニュー、複数ディスプレイ、フルスクリーンでの動作は網羅していません。
