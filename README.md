# MenuDrawer — アプリごとのアイコン表示

v0.7.0は、選んだアプリのメニューバーアイコンを表示／非表示にする小さなMacアプリです。引き出しアイコンを押し、一覧から対象を選んで切り替えます。画面収録・アクセシビリティの許可は不要です。

## 使い方

`/Applications/MenuDrawer.app`を起動して、メニューバーの引き出しを押します。

1. アプリ一覧から対象を選びます。一覧にない場合は「アプリを追加…」から選択します。追加だけでは対象アプリの設定は変わりません。
2. 対象のサブメニューで現在の表示状態と対応状況を確認し、「表示する…」または「非表示にする…」を選びます。
3. 対象アプリでの作業を保存し、録音・通信などを終えて「再起動して適用」を押します。対象アプリだけを正常終了し、表示設定を保存して起動し直します。

アプリ名の横に確認状況が出ます。

- **未検証**：設定の候補はありますが、切り替えはまだ成功確認していません。
- **一部確認済み**：このMacで表示または非表示の一方を確認しました。
- **表示・非表示確認済み**：このMacで両方の切り替えを確認しました。
- **非対応**：この方式では操作できません。サブメニューに理由を表示します。表示設定が見つからない場合や、複数アイコンの対応関係が不明な場合が該当します。

確認結果はアプリのID・バージョン・設定名・macOSバージョンに結び付けて保存します。アプリやmacOSの更新後は以前の確認済み表示を引き継ぎません。操作に失敗した側の確認結果は解除します。

画面画像の取得、カーソル移動、キー入力の送信、画面外へのアイコン移動は行いません。自動監視やログイン時の再適用も行いません。対象アプリを別途再起動すると表示が戻る場合があるため、その場合はMenuDrawerから再適用します。

## 対象の見つけ方と制約

実行中でメニューバー項目を持つアプリ、`/Applications`と`~/Applications`直下で標準のステータス項目設定を持つアプリ、手動追加したアプリを一覧にまとめます。システム項目とMenuDrawer自身は対象外です。別フォルダのアプリは手動で追加できます。

対象アプリの設定にある`NSStatusItem Visible <名前>`、または位置設定`NSStatusItem Preferred Position <名前>`から保存名を取得します。候補が一つの場合だけ操作を許可し、キーがない場合に`Item-0`などを推測して書くことはしません。アプリ独自の設定・保存方式や複数アイコンを扱う仕組みには対応しません。

この設定形式は公開された他アプリ操作APIではありません。候補が存在しても、アプリが設定を無視したり上書きしたりする場合があります。すべてのアプリで動く機能ではありません。Typeless専用の例外処理や固定アプリ一覧はありません。

起動後は、保存設定とWindowServerのウィンドウ情報（所有PID・メニューバー層・画面上の有無）で表示状態を連続して確認します。画面画像やウィンドウの内容は取得しません。この確認だけで各アプリの本来の機能が正常だと保証するものではありません。

強制終了は行いません。終了拒否、複数プロセス、選択したものと別の場所の同一IDアプリが実行中の場合は設定を書き換えません。設定変更・起動・表示確認が失敗した場合は元の設定値（未設定ならキーを削除）と元の起動状態へ戻します。復旧にも失敗した場合は、その内容を表示します。

## ビルドと検証

```sh
scripts/build.sh
scripts/test.sh
scripts/test.sh --live
```

成果物は`build/MenuDrawer.zip`です。組み立て用アプリはビルド終了時に削除します。常設するアプリ本体は`/Applications/MenuDrawer.app`の1個だけです。

通常テストでは設定の選別、操作手順、失敗時の復旧を検証します。`--live`は一時的な検証用アプリ2個を作成し、インストール済みMenuDrawerの実メニューから表示／非表示を切り替え、別アプリが変更されないことを確認します。ユーザーの通常アプリは再起動しません。終了後は検証アプリ、登録、設定、MenuDrawerの検証前設定を片付けます。

実メニューを操作するテスト用プロセスにはアクセシビリティ権限が必要です。製品本体には不要です。検証中はMacのロック解除が必要です。詳細は[VALIDATION.md](VALIDATION.md)を参照してください。
