# メニュードロワー

**選んだアイコンだけを収納し、トレイボタンからメニューバーの下に一覧を開く**小さなMacアプリです。v0.4.0から項目ごとのチェックで選べるようにしました。初期状態は未選択です。

## 使い方

`/Applications/MenuDrawer.app` を開きます。必要な権限はアクセシビリティだけです。

1. 「しまうアイコンを選ぶ」で収納したい項目にチェックし、「選択を保存」を押します。未選択のアイコンはメニューバーに残ります。手動で区切りへドラッグして配置する必要はありません。
2. トレイボタンを押すと、選んだ項目の一覧が下に開きます。クリックすると、その項目の本物のアイコンを一時表示し、元のメニューや画面を開きます。メニューを閉じると再収納します。
3. 個別に上へ戻すには、一覧の外へ項目をドラッグします。その項目の選択も解除されます。設定でチェックを外して保存する方法でも戻せます。
4. 選択を変更するには一覧の「選ぶ」、またはトレイボタンの右クリックで開きます。設定を開くだけでは収納を解除しません。選択は次回起動にも保存します。

一覧の「すべて戻す」は、意図して全解除したい場合の復旧操作です。通常は項目単位で選択を変更してください。設定画面の「終了」で収納を解除して終了します。ログイン時の自動起動は設定していません。

時計とコントロールセンターなど、macOSの固定項目はチェックを無効にして常時表示します。

## 権限と動作の限界

**画面収録は使用しません。** 一覧の画像には通常のアプリアイコンを使い、名前・操作対象をアクセシビリティから取得します。画面やウィンドウの画像を収録せず、ネット送信も行いません。ウィンドウの位置情報は対象の識別とメニュー表示の確認に使用します。

画面収録を許可しても、アイコンの移動や収納の制御が正確になるわけではありません。本物のステータスアイコンの絵柄を画像で表示する場合に必要になる権限です。現在の画像は本物のステータスアイコンとは異なり、状態表示はアプリが公開する文字情報によります。

macOSの既存のステータス項目を、別のパネルへ直接移設する公開APIはありません。本物のメニューを開く間は選んだアイコンをメニューバーへ取り出すため、その付近の配置は変わります。内部のマウス操作中はカーソルを隠し、元の位置へ戻してから再表示します。選択変更で移動が不要な項目は動かしません。失敗時に突然全収納・全解除する処理は廃止しました。

アクセシビリティから一意に特定できる項目を選択対象としています。各アプリの全操作、複数ディスプレイ、フルスクリーンは網羅していません。検証環境はApple Silicon / macOS 15.8.1です。

現在のmacOS 15.8.1では、コントロールセンターの内部に追加できる公開の拡張APIはありません。macOS 26 Tahoeには[サードパーティのControls API](https://images.apple.com/os/pdf/All_New_Features_macOS_Tahoe_Sept_2025.pdf)があります。このAPIで一覧を開く入口を追加することと、他アプリの既存アイコン・メニューを内部へ移設することは別の機能です。このアプリにはコントロールセンター拡張を実装していません。

## ビルドと検証

Xcode Command Line ToolsのSwiftでビルドします。外部パッケージは使用しません。ビルド先は `build/MenuDrawer.app` で、インストール済みアプリは自動では上書きしません。

```sh
scripts/build.sh
scripts/test.sh
scripts/test.sh --integration
scripts/test.sh --real
```

統合検証は端末のアクセシビリティ権限を使用します。通常起動中のMenuDrawerを終了してから実行してください。アプリの選択設定を一時的に変え、終了時に元へ戻します。検証用のプロセスも終了します。

- `--integration`: 別プロセスの本物のアイコン操作、項目を一つ選んで収納、未選択項目の表示維持、実クリックから元メニュー・通常画面の表示、再収納、実ドラッグで取り出し、選択の解除と全解除。
- `--real`: 実アプリを一つずつ選択して切り替え、ほかの項目が表示されること、設定を開いても収納を維持すること、再起動後の選択保持、元メニューの表示維持と閉じた後の再収納。メニュー項目は選びません。

画面収録が未許可の状態で、配置境界の8検証と上記の検証に成功しました。ChatGPT、UltraScale、入力メニュー、バッテリー、Wi‑Fiでも選択収納と元メニュー表示を確認しました。更新した `/Applications/MenuDrawer.app` もアクセシビリティへ再登録し、通常起動で許可済みと認識されることを確認しました。その同じプロセスで、項目の選択・実クリックから元メニュー表示・再収納・実ドラッグで取り出し・全解除まで成功しました。実アプリ5項目についても、個別の選択収納と元メニュー表示を再確認しました。

`--validation-output` と `--preview` は、指定した出力先へアプリ自身のビューの描画だけを保存する検証用オプションです。画面全体や他アプリを撮影しません。ビューの描画画像には、macOSの合成する背景・標準コントロールの一部が含まれない場合があります。

## 署名と再登録

ローカル用のアドホック署名で、Appleの配布用公証は行っていません。再ビルドで署名が変わると、設定上はオンでもアプリが「未許可」と認識する場合があります。その場合はアプリを終了し、「プライバシーとセキュリティ → アクセシビリティ」で古いMenuDrawerを削除して、現在の `/Applications/MenuDrawer.app` を追加し直します。

実装にはSwift・AppKit・アクセシビリティ・CGEventを使用します。収納は幅の大きいNSStatusItemと項目ごとの配置制御で実現します。イベントの対象ウィンドウ指定には、公開名のないフィールド番号51も使用しており、将来のmacOS変更に影響される可能性があります。
