# メニュードロワー

メニューバーのトレイボタンを押すと、収納したアイコンをメニューバーの**下**に展開する小さなMacアプリです。画面収録を使わず、**アプリの通常アイコン＋名前**を縦に並べます。項目をクリックすると本物のアイコンを一時的に表示し、元アプリのメニューや画面を開きます。

## 起動

`/Applications/MenuDrawer.app` に配置済みです。Finderの「アプリケーション」から **MenuDrawer** を開いてください。検証環境は Apple Silicon / macOS 15.8.1 です。

1. 設定画面の「権限を設定」から、macOSの設定で **MenuDrawerのアクセシビリティだけ**を許可します。画面収録は不要です。
2. ⌘キーを押しながら、収納したいアイコンをメニューバーの「│」より左へ移動します。「│」自体はトレイボタンの左に置きます。右側のアイコンは常時表示されます。
3. 「収納を開始」を押します。以降はトレイボタン1つで開閉できます。パネル外のクリック、Escでも閉じます。
4. 一覧の項目をクリックすると元のメニューや画面を開きます。メニューを閉じるとアイコンを再収納します。
5. 一覧の外へ項目をドラッグすると、本物のアイコンをトレイボタンの右に取り出して常時表示します。
6. 一覧の「すべて戻す」で全アイコンの収納を解除できます。配置の変更や終了は、トレイボタンの右クリックからも操作できます。

アプリを再ビルドしたあと、設定上はオンでもアプリが「未許可」と表示することがあります。ローカル用の署名が更新されるためです。その場合はアプリを終了し、macOSの「プライバシーとセキュリティ → アクセシビリティ」で古いMenuDrawerを削除して、現在の `/Applications/MenuDrawer.app` を追加し直してください。

macOSが移動を許可しない時計などの固定項目は、そのまま表示します。ログイン時の自動起動は設定しません。

## 最小限の権限

**必要なのはアクセシビリティだけです。** 項目の名前と位置を読み、選んだ項目のメニューを開くために使用します。アイコン画像には各アプリが提供する通常のアプリアイコンを使います。

画面収録API、画面収録ライブラリ、その権限確認・要求はすべて削除しました。画面やウィンドウの画像を取得せず、ネット送信も行いません。ウィンドウの位置情報は、収納対象の判定とメニューが開いたことの確認に使用します。

メニューバー固有の絵柄や点滅などは再現しません。アプリがアクセシビリティで項目名や状態を公開していれば、パネルを開くときに文字として取得します。アプリアイコンがない場合は汎用アイコンを表示します。

アクセシビリティで一意に特定できた項目だけを表示します。対応していないアプリのアイコンは、配置設定で区切りの右側へ戻して元の場所で操作してください。メニューの表示を確認できない場合は本物のアイコンを外に残します。移動に失敗した場合は収納を解除し、元のメニューバーから操作できる状態へ戻します。

## ビルドと検証

Xcode Command Line Tools のSwiftだけでビルドできます。外部パッケージは使用しません。ビルド先はソースフォルダ内の `build/MenuDrawer.app` で、配置済みのアプリは自動では上書きしません。

```sh
scripts/build.sh
scripts/test.sh
scripts/test.sh --integration
scripts/test.sh --real
```

統合検証は実行する端末のアクセシビリティ権限を必要とします。通常起動中のMenuDrawerを終了してから実行してください。検証用プロセスとアプリを起動し、以下を確認します。終了時には検証プロセスを停止します。

- 画面収録の許可状態を記録し、収納した項目の通常アイコン・名前・操作対象を取得する。
- 別プロセスの収納中の項目を取り出し、本物のアイコンをクリックして元メニューが表示される。
- 設定画面、トレイボタン、パネル内の項目を実マウス入力で操作する。
- メニューバーの下のパネルから、元のメニューと通常ウィンドウの両方を開ける。
- メニューを閉じた後の再収納、一覧外への実ドラッグで常時表示、「すべて戻す」による収納解除が動作する。

`--real` は起動中の実アプリについて、一覧のクリックから元メニューの表示、0.8秒後も表示が維持されること、Escで閉じた後の再収納を確認します。実アプリのメニュー項目は選択しません。

`build/tests/panel.png` はテスト中のパネル自身のビューを描画した画像です。画面全体や他アプリを撮影したものではありません。`--validation-output` と `--preview` は明示した出力先へアプリ自身の描画結果だけを保存する検証用オプションです。

```sh
build/MenuDrawer.app/Contents/MacOS/MenuDrawer --preview /絶対パス/preview.png
```

## 実装と検証範囲

Swift + AppKitで新規実装しています。収納には幅の大きい `NSStatusItem`、対象の識別にはアクセシビリティ、移動・クリックには `CGEvent` を使用します。イベントの対象ウィンドウ指定には、公開名のないフィールド番号51も使用しています。macOSの将来の変更に影響される可能性があります。ローカル用のアドホック署名で、配布用のApple公証は行っていません。

v0.3.0では、macOS 15.8.1で、画面収録が未許可のままビルド、配置境界の8検証、別プロセスのアイコン操作、実クリック・実ドラッグの統合検証に成功しました。UltraScale、ChatGPT、入力メニュー、バッテリー、Wi‑Fiの実アイコンでも表示と再収納を確認しました。実パネルの文字と通常アイコンは、パネル自身の描画画像で目視確認しています。更新後の `/Applications/MenuDrawer.app` もアクセシビリティへ再登録し、通常起動で許可済みと認識されることを確認しました。その同じプロセスで、実クリックから元メニュー表示・再収納・実ドラッグで取り出し・全解除まで成功し、上記5項目の表示と再収納も再確認しました。

各アプリの全操作、複数ディスプレイ、フルスクリーンでの動作は網羅していません。
