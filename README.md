# MenuDrawer — 選んだメニューバーアイコンを収納

v0.8.0（ビルド12）。選んだメニューバーアイコンを収納し、独立ウィンドウで管理します。Dockには表示せず、MenuDrawer自身のメニューバーアイコンも初期状態で非表示です。画面を閉じても収納を続け、アプリを再度開くと同じプロセスの画面を再表示します。確認範囲と過去の修正は[VALIDATION.md](VALIDATION.md)に記載しています。

公開リポジトリは[GitHubのtndd/menu-drawer](https://github.com/tndd/menu-drawer)です。

アイコンは、左の中抜きで「収納できるアイコン」、右の塗りつぶしで「収納中」を表します。アプリ本体は光の反射を抑えた青いガラス調、メニューバーは同じ形の18ptテンプレート画像を使い、明暗の色はmacOSに合わせます。

## 操作

SpotlightやランチャーからMenuDrawerを開くと、移動できる独立ウィンドウを表示します。起動済みの場合は同じプロセスの画面を再表示します。Dockには表示しません。

左側は「収納できるアイコン」、右側は「収納中」です。各一覧に件数を表示し、時計などのmacOS固定項目は操作対象から除きます。

- 「macOS標準の項目を表示」は初期状態でオフです。チェックを入れると、Wi-Fi・音量・バッテリー・入力メニューなど、移動できるmacOS標準項目も収納候補に表示します。チェック状態は次回起動にも引き継ぎます。収納済みの標準項目はオフでも右側に残り、個別に取り出せます。時計など移動できない保護項目は、オンでも候補に含めません。
- 左側の右矢印を押すと、そのアイコンだけを収納して右側へ移します。
- 右側の左矢印を押すと、そのアイコンだけを元の並びへ取り出して左側へ移します。
- 「全て取り出す」で収納を解除します。収納が空になると、境界用のステータス項目自体を撤去します。
- 「メニューバーアイコンを非表示」は初期状態でオンです。オフにするとMenuDrawer自身の操作アイコンを表示し、押すと独立ウィンドウを開きます。この設定は次回起動にも引き継ぎます。
- 赤い閉じるボタンは画面だけを閉じます。収納状態とバックグラウンド動作は維持します。
- 終了するときは画面内の「MenuDrawerを終了」を使います。通常終了ではアイコンを戻し、次回起動時に保存済みの選択を再適用します。

アプリの再起動や、対象アプリの設定値の書き換えは行いません。収納・取り出しはアイコンごとの操作です。同じアプリに複数のアイコンがある場合も、個別のウィンドウを対象にします。

操作アイコンを表示する場合は、収納境界の右側にあることと、収納後も画面外やノッチの裏に隠れないことを確認します。非表示を選んだ場合は、操作アイコンが存在しなくても収納できます。収納処理が失敗した場合は追加のドラッグを行わず、透明な境界と収納状態、保存済みの選択を撤去します。エラー後の元の並びまでは保証できません。

## 権限と署名

アイコンの移動にはアクセシビリティが必要です。画面収録は不要です。画像取得、画像の複製表示、収納アイコンの代理クリックは行いません。

通常利用で必須の許可はアクセシビリティだけです。入力監視、フルディスクアクセス、管理者権限は要求しません。以下の署名鍵の利用承認はビルド時の準備であり、製品の通常動作で使う許可ではありません。

設定画面は、ユーザーが画面内の「アクセシビリティを許可…」を押した場合だけ開きます。起動時、切り替え時、失敗時に設定画面へ自動遷移する処理はありません。OSの権限要求ダイアログを自動で出す処理もありません。

旧版では仮署名を用いており、コードの版ごとに識別条件が変わりました。今後は `MenuDrawer Local Signing` の固定証明書を使います。秘密鍵はキーチェーンに保存し、ビルド時だけmacOS標準の `/usr/bin/codesign` が使用します。製品の通常動作では署名鍵を使用しません。

初期準備の認証は別々です。

1. 証明書をコード署名用途として信頼する設定の承認。
2. `codesign`がその秘密鍵を利用する承認。OSの鍵利用ダイアログで、この専用鍵について`codesign`を「常に許可」した場合に継続利用できます。
3. アプリがメニューバー項目を移動するための初回アクセシビリティ許可。

証明書の信頼だけでは秘密鍵の利用やアクセシビリティまで許可されません。このMacでは専用鍵を許可した後の再ビルドが追加の鍵利用確認なしで成功し、ビルド1から2への更新後にもアクセシビリティを再登録せず収納・取り出しができました。

旧仮署名の許可が残った場合、スイッチをオンにするだけでは新署名への許可に置き換わらないことがありました。今回の移行では、MenuDrawerだけの旧登録を削除し、現在の`/Applications/MenuDrawer.app`を追加し直して、許可の署名条件が固定証明書と一致することを確認しました。通常の更新処理は許可をリセットしません。

## 収納の仕組み

Iceのコミット `11edd39115f3f43a83ae114b5348df6a0e1741cf` を調査しました。詳細とライセンスは[THIRD_PARTY.md](THIRD_PARTY.md)に記載しています。

メニューバーの実ウィンドウを列挙し、対象のウィンドウIDを指定したCommandドラッグ相当の操作で、収納境界の左へ移動します。境界を広げて選んだアイコンを画面外へ退避させます。追加収納・個別取り出しでは境界全体を展開しないため、既に収納した別アイコンを一斉に再表示しません。

移動イベントはPIDとセッションの両経路で到達を確認し、移動後の位置も検査します。マウス操作や修飾キー入力中は移動を開始しません。位置の安定待ちの間に操作が再開された場合も、入力停止と位置の安定を確認し直します。待機開始から3秒を過ぎても入力が止まらない場合は、イベント送信前に中止します。カーソル位置を保存し、移動中は非表示にし、成功・失敗の両方でボタン解放と位置の復元を行います。

収納が空の時点の全体順序を保存し、複数を収納しても画面外へ移った項目の物理位置で上書きしません。操作アイコンを表示している場合は、復元先にMenuDrawer自身のボタンも含めます。前の移動によるアニメーションが終わる前の座標を使わないよう、移動の開始前と完了時に位置が安定していることを確認します。

アプリの起動・終了、ディスプレイ変更の通知時に状態を照合します。新規に左端へ追加された未選択アイコンを、収納側に置いたままにしない処理を含みます。

## 制約

- 時計、コントロールセンター本体、Siri、録画・録音などの保護表示は、IceにもあるmacOS側の制約に従います。アプリ固有の表示設定がないことを理由に、通常アプリを一括で非対応扱いにする方式ではありません。
- アプリをまたいでアイコンを移動する公開APIはなく、Iceと同様にWindowServerの非公開API・イベントフィールドを使用します。検証環境はmacOS 15.8.1、Apple Silicon。別のOS版での動作は未検証です。
- 選択の保存は、単一アイコンならアプリID、複数なら一意の識別子を用います。識別子がない複数アイコンも実行中は個別に操作できますが、再起動後に別アイコンを推測して選択しません。
- 収納中に残りのアイコンが空いた場所へ詰まるのはmacOSの配置動作です。取り出し後の元の相対順序は保持しますが、時計などの表示幅、画面構成、対象アプリの終了・再起動が変わる条件で、元のピクセル座標そのものまでは保証しません。
- 強制終了時は非同期の位置復元を実行できません。境界自体はプロセス終了で消えますが、元の並びの保証は通常終了を対象にします。
- マルチディスプレイ、フルスクリーン、画面接続変更後の全経路は未検証です。

## ビルド・配置・検証

下記の`--native`・`--real`・`--live`は他アプリの項目を移動するため、ユーザーがマウスやキーボードを操作しない時間に実行してください。`--live`は元の相対順序と、非表示時に操作アイコンの領域が残らないことも検査します。空白の検証だけなら`test_spacing.sh`を使用します。

```sh
scripts/test.sh
scripts/test_window.sh
scripts/test.sh --native
scripts/test.sh --real
scripts/build.sh
scripts/install.sh
scripts/test.sh --live
scripts/test_spacing.sh
```

`--native`は一時的な検証アプリ2個の収納・取り出しと、3個目の新規起動を検査します。検証後にアプリ・設定・登録を片付けます。`--real`はChatGPTと入力メニューの実アイコンを、同じ収納エンジンを使う独立した検証プロセスから操作して元へ戻します。`--live`はインストール済みアプリの実ウィンドウを操作し、専用の検証アイコンだけで収納・取り出し、画面を閉じた後の維持、再呼び出し、非表示設定、通常終了と再起動を確認します。いずれもMacのロック解除が必要です。これらの確認は相互の代用にはしません。

`test_window.sh`は自アプリのネイティブ画面で左右の一覧の寸法、下部チェック、マーク操作、処理中・未許可時の操作制限を検査し、`build/tests/window-screen.png`へ表示画像を保存します。検証プロセス自身のウィンドウだけを撮影し、製品に撮影処理は追加しません。

`test_spacing.sh`はアクセシビリティ未許可の一時アプリで、表示幅と、移動イベント生成前の失敗時に透明な境界が撤去されることを確認します。他アプリの収納・取り出しは行いません。`install.sh --no-launch`は配置後の自動起動を省略し、保存済みの選択が起動時に再適用されるのを避ける場合に使います。

`build.sh`は固定署名がない場合、通常ビルドを中止します。成果物は `build/MenuDrawer.zip` です。署名が失敗した場合は新しいZIPを書き出しません。`install.sh`は署名の検証を済ませてから起動中アプリを終了し、`/Applications/MenuDrawer.app`の一つだけへ配置します。仮署名版を通常インストールすることは拒否します。

専用証明書の初期作成スクリプトは `scripts/create_signing_identity.sh` です。キーチェーンへ鍵とコード署名用の信頼設定を追加するため、ユーザーの明示承認を得た場合にのみ実行します。既に同名の証明書がある場合は重複作成しません。
